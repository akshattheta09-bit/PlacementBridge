# Permission model
Default deny. Each request resolves an active user and active, unexpired role assignments from the database. Institution must match the resource. Roles are explicitly assigned; an email domain never confers authority. Student: published announcement read. Placement officer: draft, submit, review and publish, with a different user required to approve. Reviewer and administrator dashboards confer no grievance access or announcement authority. Multi-role users receive the union of approved roles, subject to resource scope and separation of duties. Department-specific access is not yet supported and must not be represented as enforced. Future confidential cases require ownership or explicit assignment and conflict-of-interest checks. Server actions are independently authorized, not merely hidden in the UI.
